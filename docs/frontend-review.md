# フロントエンドのレビュー案内

画面案を確認用の基準版として共有します。デザイン以外の処理・入力検証・保存状態の修正は、基準版から分けたブランチで差分を確認します。このブランチは完成形の画面と操作を検討するフルモックで、mainへの取り込み可否は別途レビューで判断します。モックであることを理由に、入力検証や状態管理の確認を省く意図はありません。

## 画面の確認

`frontend/README.md` の手順で起動します。

| 確認したいこと | 操作 |
| --- | --- |
| 全体の導線 | 一般フィード → 記事のページ表示 → 一覧に戻る |
| 入力と関連情報 | 設定で複数URLを登録 → 切替 → 関連度順、CVSSと対応優先度を比較 |
| 保存とコメント | 記事を保存 → 保存済み一覧 → コメント追加・削除 |
| ログイン状態 | ゲストで操作 → 新規表示名でログイン → ログアウト → 同名で復元 |
| 小さい画面 | スマホ幅で検索・並び替え → 記事を開く → 一覧へ戻る |
| 機能を絞った案 | `?view=mvp` を開いてフル版と比較 |
| 読み込み失敗 | `?scenario=error` で再試行を確認 |

データ・認証はブラウザー内の再現です。API接続の不足は [連携メモ](frontend-integration.md) にまとめています。

## コードを読む順番

| 対象 | ファイル | 主な確認点 |
| --- | --- | --- |
| 入出力 | `frontend/src/types/` | CVSSとリポジトリ優先度の区別、必要な情報 |
| 取得境界 | `services/feed.ts` とテスト | URL検証、検索・並び順、キャンセル、モックの分離 |
| 保存境界 | `services/workspace.ts` とテスト | ゲストとプロフィールの分離、入力制限、保存失敗 |
| 画面の接続 | `App.vue`、`composables/` | 遷移・選択・読み込み・エラーの整合性 |
| 表示と操作 | `components/` | 入力エラー、キーボード、リンク、文字列の描画 |
| 見た目 | `styles.css`、`DESIGN.md` | 文字サイズ、余白、並び替え矢印、レスポンシブ |

`pnpm test` と `pnpm build` で取得・保存境界のテスト、VueとTypeScriptの型チェック、ビルドを確認できます。

## 処理・入力検証の修正

基準版との差分は `codex/frontend-mock...codex/frontend-hardening` で確認できます。[診断・改修の記録](frontend-security-review.md) に、再現条件、修正、実行した確認、本実装への持ち越しをまとめています。

## 本実装を取り込むときの分割候補

チームとレビュー目的を揃えた上で、動作を一つ確認できる単位にします。

1. フロントエンドの起動基盤と一般フィード・記事詳細
2. リポジトリ登録・入力検証・関連フィード
3. ログインと保存状態の連携
4. 保存済み一覧・コメント
5. リポジトリの対応状況と分析結果・PoCの表示

これは提出案です。今あるPRを自動で分割したり、コミット履歴を書き換えたりはしていません。APIや認証の合意に応じて粒度と順番を調整します。同じ大きなPRへ何回pushしても、差分全体のレビュー量は減りません。
