# フロントエンドのAPI接続

通常起動・配布用ビルドは `ApiApp.vue` から既存Go APIを呼び出します。`PreviewApp.vue` は `VITE_FEED_SOURCE=local` を明示した開発サーバー専用です。通常画面へローカルの架空記事・プロフィール・解析タイマーを混ぜません。

## 現在の接続先

| 操作 | 既存API |
| --- | --- |
| 一般フィード | `GET /api/cves?limit=200` |
| 一般の記事詳細 | `GET /api/cves/{cve_id}` |
| URLの明示登録 | `POST /api/repositories`、本文 `{ "url": "https://github.com/owner/repository" }` |
| 解析状況 | `GET /api/jobs/{job_id}` |
| 関連フィード | `GET /api/repositories/{repository_id}/feed` |
| 関連記事の詳細 | `GET /api/repositories/{repository_id}/feed/{cve_id}` |

契約の正本は `server/model/types.go` と `server/api` です。受信値は `services/feedApi.ts` と `feedContract.ts` で検証します。現在のサーバーは固定データを返すモックで、登録本文を処理せず、ジョブは完了状態を返します。LLMの `feed.Item`、SQLiteのCRUDとはまだ接続されていません。この変更にはバックエンドの追加実装を含めません。

## 状態と操作

- リポジトリのPOSTは「読み込む」を押したときだけです。記事URLを開いただけでは登録しません。登録が必要な共有リンクでは、URL入りの入力欄を表示します。
- 登録IDと最後に選んだ公開URLは同じタブのsessionStorageに保持します。壊れた保存値は採用せず、保存できない場合も現在の画面で操作を続けられます。認証・所有権の根拠には使いません。
- 同じURLの同時登録はまとめます。送信済みPOSTの待機を画面遷移で止めても、応答を受け取れた登録IDは保持します。応答そのものを失った場合の重複防止には、将来バックエンド側の冪等性契約が必要です。
- ジョブは1秒間隔、最大60回確認します。1リクエストは本文の読み取りを含め15秒で打ち切ります。60回終了はジョブの失敗と断定せず、状態の再確認を案内します。
- 途中結果が利用可能なら表示し、後続の失敗でも取得済み記事を残します。「再試行」は同じジョブの再確認で、解析を再実行するAPIは呼びません。
- 一覧と記事詳細は別々に取得します。詳細URLの表示は、一覧の成功や最大200件の取得範囲に依存しません。
- 検索・深刻度・並び替えは取得済みの記事に対して行い、操作ごとにAPIを呼び直しません。全件数が取得数を超える場合は検索対象の範囲を画面に示します。ページングAPIの追加は別途必要です。
- 表示対象の切替では古い応答を捨てます。同じ一覧を再取得する間は記事を残し、詳細から戻った際の選択・スクロール位置を維持します。
- 未評価、関連判定なし、解析未完了の記事は、関連フィードの一覧・詳細とも未確定として扱います。返却値に暫定の関連度や優先度が含まれていても確定表示しません。

## 画面で提供する機能

一般／関連フィード、検索、絞り込み、並び替え、記事詳細、共有、参照リンク、APIが返すPoCのテキスト表示です。既存の配色と一覧・詳細の配置を使います。

ログイン、保存、コメント、対応状況の記録、個別解析・定期追跡、過去情報の再検索は対応APIが未提供のため、開発用デザイン確認画面に残しています。通常画面で成功したように見せるローカル代替処理は行いません。

## データとセキュリティの境界

API応答の型・日時・件数・IDを検査し、HTTPエラー本文やジョブの内部診断文を利用者にそのまま表示しません。文字列はVueでエスケープし、外部リンクは既存のURL検証を通します。PoCを実行する機能はありません。

公開GitHub URLの形式検証はフロント側でも行いますが、存在確認、アクセス権、SSRF対策、登録の重複防止はサーバー側の責務です。認証情報をURLやブラウザー保存へ追加しません。

## ローカル検証

[起動手順](../frontend/README.md)に従いGo APIを起動後、frontendで実行します。

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e:api
pnpm test:e2e:production
pnpm test:e2e
```

API E2EはGoのHTTP応答を使用します。進行中・部分失敗・通信障害など、現在の固定APIが返さない状態だけをブラウザーで差し替えて検証します。既存のデザイン確認画面は別のE2Eで検証します。CIは追加しません。
