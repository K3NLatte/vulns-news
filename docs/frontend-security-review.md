# フロントエンドの処理・入力検証レビュー

確認日: 2026-09-25
基準版: `codex/frontend-mock` / `715496e`
修正ブランチ: `codex/frontend-hardening`

画面の基準版を保ち、入力・保存・解析依頼の状態管理を確認しました。対象はブラウザー内で動くモックです。API、認証、クロール、LLM処理の本実装は今回の診断対象に含みません。

## 修正した問題

| 対象 | 再現した問題 | 修正と回帰確認 |
| --- | --- | --- |
| リポジトリURL | 大小文字の違いで同じリポジトリを別の解析依頼として扱う。正規化だけ変えると旧保存データを復元できなくなる | URLを小文字に統一。表示名は保持し、旧保存形式も読み込む。重複登録・再読み込みをテスト |
| 入力とリンク | URL入力と出典リンクで検証条件が異なる。型違い・不正なUnicodeを渡すと処理が例外になる | HTTPSリンクの構文検証を共通化。認証情報、独自ポート、制御文字、IPアドレス等を拒否。URLの意味を持つクエリは保持 |
| 長い脆弱性ID | 入力を受理して作成した記事が、内部IDの文字数制限により保存・コメントできない | 長いIDには短い内部キーを付与。表示するIDは維持。記事作成→保存→コメント→対応状態をテスト |
| プロフィール保存 | プロフィール保存成功後、アクティブ状態の保存だけ失敗すると、ゲストの作業を失う | 両方の保存が成功するまでゲストデータを消さない |
| 保存データの読込 | 読込失敗・破損JSON・保存値nullを「未作成」と扱い、既存プロフィールを上書きする | 未作成と読込失敗を区別。読めないプロフィールへのログインを拒否し、保存値を維持 |
| 名前・保存サイズ | Unicode正規化で名前が伸びると復元できない。保存側の文字数上限が読込側と一致しない | 正規化後のキーを復元可能にする。単独サロゲートは拒否。保存・読込の上限を揃え、保存失敗時は直前の保存値と画面内の変更を保持 |
| 解析依頼の上限 | 拒否した依頼の状態が残る。失敗した依頼の再試行で同時5件上限を回避できる | 上限・重複の確認後に依頼を登録。新規・再試行・復元で同じ上限を適用 |
| 解析履歴の復元 | 不正な型・日時・状態・履歴を復元し、例外や意図しない完了扱いになる | 保存データ専用のパーサーで型、列挙値、日時、履歴整合性、既知のIDを確認。不正な行を除外 |
| 取消と定期更新 | 未完了で取消した依頼でも、追跡期間を更新すると翌日に解析済み扱いになる | 定期更新は既に解析済みのレポートだけを対象とする。取消済み情報を公開一覧へ戻さない |

主な変更は `services/feed.ts`、`utils/publicUrl.ts`、`services/workspace.ts`、`services/reports.ts`、`services/reportSession.ts`、`composables/useReportLibrary.ts` と、それぞれのテストです。

## API接続時に残ること

プロフィール切替はブラウザー内のモックです。localStorage/sessionStorageは利用者が変更できるため、ログイン、権限、分析済みの証明には使いません。コメントの所有者や更新権限はサーバーで確認する必要があります。

公開HTTPS URLの検査は入力構文の確認です。DNSの名前解決先やリダイレクト後の接続先は判定していません。実際にURLを取得するバックエンドで、内部ネットワークへのアクセスを制限してください。

APIレスポンスの実行時検証、セッション方式に応じたCSRF対策、認可、サーバー側の入力検証・件数制限はAPIの契約が決まった段階で接続・確認します。既存の取得キャンセルと古いレスポンスの破棄処理は維持しています。

確認に使った基準: [Vueのセキュリティ指針](https://vuejs.org/guide/best-practices/security.html)、[OWASPの入力検証](https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html)、[OWASPのブラウザー内保存に関する指針](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html)。
