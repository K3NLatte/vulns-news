# フロントエンド

Vue + TypeScriptで、画面と操作を検討しながら、バックエンド接続後も育てていくフロントエンドの実装基盤です。採用未定の機能も含めて完成形を試せます。

現在の記事・製品・解析・スコアは架空データで、API、クローラー、LLM、認証サーバーには接続していません。接続時に置き換える処理と未合意の要件は、この文書と[連携メモ](../docs/frontend-integration.md)で管理します。

## 起動

WSL Ubuntu-24.04でリポジトリのルートへ移動して実行します。

```bash
nix develop .#
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

- フル版: http://localhost:5173/
- MVP版: http://localhost:5173/?view=mvp

同じコンポーネントと取得処理を使い、MVPでは機能を絞って表示します。開発サーバーはWindows側の保存を検知するためポーリングを使います。

この手順では依存関係のインストール・起動・テストをWSL側でそろえます。Windows側のpnpmとWSL側の`node_modules`は混在させないでください。OS依存のバイナリが含まれるため、Windowsでも作業する場合は別のチェックアウトを用意し、その環境で依存関係をインストールします。`nix develop .#`は、`path:.`で未追跡の`node_modules`までコピーする待ち時間を避ける指定です。

## 画面と操作

| 機能 | フル版 | MVP版 |
| --- | --- | --- |
| 一般フィード、検索、CVSS重要度、新着順・重要度順 | 対応 | 対応 |
| 公開リポジトリURL、関連度順、対応優先度 | 対応 | 対応 |
| 記事詳細のサイド表示、独立したページ表示 | 対応 | 対応 |
| 複数リポジトリの登録・切替・削除 | 対応 | 単一URLの入力 |
| ログイン・ログアウト、プロフィールの切替 | 対応 | なし |
| 記事の保存、保存済み一覧 | 対応 | なし |
| コメント追加、自分のコメント削除 | 対応 | なし |
| リポジトリごとの未確認・調査中・対応済み・影響なし | 対応 | なし |
| PoCの静的なコード表示 | 対応 | なし |

左の一覧は固定高を設けず、ページ全体でスクロールします。PCでは右の記事が画面に追従し、見出し・操作を残して本文だけをスクロールできます。上部の操作欄が画面外へ流れると、右の記事も画面のほぼ全高を使います。非常に長い見出しで本文の余地が足りなくなる場合だけ、右の詳細全体をスクロールする方式へ切り替え、本文まで到達できるようにします。

幅1000px未満、または画面高が500px × 文字拡大率未満の場合は一覧を1列にし、記事を選ぶとページで開きます。文字拡大率はルートの文字サイズを16pxで割った値です。「ページで開く」はPCでも使え、URLから直接開けます。

リポジトリ向け表示ではCVSSと別に対応優先度・関連度・依存関係・判断理由を表示します。関連度順はリポジトリを指定した場合だけ選べます。

## 再現用のデータ

一般フィードは12件です。リポジトリの owner/name を正規化し、文字コードの合計を3で割った余りで固定プロフィールを選びます。リポジトリの実在確認、公開状態確認、依存関係の取得はしません。

- https://github.com/example/frontend : Web系の6件
- https://github.com/example/backend : API系の5件
- https://github.com/example/tooling : ツール系の4件

どのプロフィールでも関連度、CVSS、対応優先度は別々の値です。根拠のある実スコアへ置き換えるにはバックエンドとの契約が必要です。

CWE等の外部リンクは一般的な技術資料です。架空の記事を裏付ける公開アドバイザリではありません。PoCは example.invalid を宛先としたテキストで、実行ボタンや自動通信はありません。

## ログインと保存の再現

ログイン画面の表示名で、このブラウザー内のプロフィールを選びます。パスワードやOAuthは使わず、本人確認も行いません。本番の認証として使用できません。

ゲストのリポジトリ・保存・コメント・対応状況はsessionStorageに保持します。ログイン後のプロフィールはlocalStorageに保持し、同じ表示名で再度開くと復元します。新しいプロフィールに初めてログインするとゲスト内容を移し、保存成功後にゲスト側を空にします。既存プロフィールへのログインではゲスト内容を別に保持します。

追加入力から作った記事を保存すると、正規化したCVE・GHSA・URLと作成日時をプロフィールに保持します。解析セッションがなくなっても、同じプロフィールの保存済み一覧から「未確認／未評価」の記事として復元できます。保存データ中の本文、CVSS、解析完了状態を信頼して復元する仕組みではありません。プロフィールからログアウトすると、そのプロフィールだけに保存された記事は表示しません。

コメントはこのブラウザー内だけのデータです。ほかの利用者へ投稿されません。表示名やコメントにはレビュー用の情報を使ってください。API接続時はこの保存処理を置き換え、認証・認可をサーバー側で実装します。

## 状態確認

画面に開発用スイッチを置かず、URLで取得状態を指定できます。

- ?scenario=loading
- ?scenario=empty
- ?scenario=error

MVPでは ?view=mvp&scenario=error のように組み合わせられます。エラー画面の「再試行」で通常表示へ戻ります。

## 解析待ちのデザイン確認

登録済みリポジトリがある状態で、`?analysis=analyzing#/repositories` のように指定します。

| analysisの値 | 表示 |
| --- | --- |
| queued / profiling / matching | 解析待ち・構成確認・照合。一般フィードは閲覧可能 |
| screening | 関連性の選別中。未確定の記事を先に表示 |
| analyzing | 詳細分析中。途中まで得られた結果を表示 |
| completed（既定） | 分析済みと未確定を分けて表示 |
| failed | 部分結果を維持し、再試行の導線を表示 |

画面を比較するための固定状態です。実際の解析開始・進捗取得・再開はしません。再試行は表示をanalyzingへ切り替えるだけで、自動的には完了しません。割合や残り時間を推測して表示しません。

未確定は関連性を判定できなかった結果です。処理の失敗や「影響なし」とは区別し、確定した優先度・関連度スコア・生成済みの対策やPoCを表示しません。モックでは固定IDで状態を割り当て、検索や並び替えで解析結果が変わらないようにしています。

画面案を基準版としてpushし、以後の処理・入力検証・保存状態の修正は基準版から分けたブランチで提出します。基準版の共有はmainへのマージや、個別解析構想のチーム合意を意味しません。

## 実装の境界

- App.vue: 画面間の接続と選択状態
- composables/useNavigation.ts: ハッシュによるページ移動
- composables/useFeed.ts / services/feed.ts: 非同期取得とキャンセル
- composables/useWorkspace.ts / services/workspace.ts: リポジトリ、プロフィール、保存、コメント、対応状況
- composables/useReportLibrary.ts / services/reports.ts / services/reportSession.ts: 解析依頼、追跡、履歴と保存した入力からの記事復元
- composables/useFeedPanes.ts: 一覧の文書スクロールと詳細の高さ・スクロール方式
- components/: 表示とユーザー操作
- mocks/feed.ts: 固定データ

API連携の確認事項は [連携メモ](../docs/frontend-integration.md)、文字サイズと色は [DESIGN.md](../DESIGN.md)、確認する順番は [レビュー案内](../docs/frontend-review.md) を参照してください。

## 検証

以下は`frontend`で実行します。

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install --with-deps chromium firefox
pnpm test:e2e
```

`typecheck`はアプリとE2Eコードの型を確認します。`test`はVitest、`build`は型チェックと配布用ビルドです。Playwrightのブラウザー導入は初回とバージョン変更時に必要です。Linuxのシステム依存関係を導入する`--with-deps`は管理者権限を要求する場合があります。

E2Eは[frontend.spec.ts](e2e/frontend.spec.ts)のシナリオをChromiumとFirefoxで実行する構成です。件数と実行結果は品質レビュー記録に集約します。標準ではテスト用の開発サーバーを`127.0.0.1:4173`で起動します。検索・絞り込み、Indeed型スクロール、複数リポジトリ、プロフィールとコメント、保存記事の別セッション復元、解析の重複・中止、壊れた保存データ、共有、保存拒否、表示状態、文字拡大、MVP、長文、タブ間の保存競合を確認します。axeによる自動アクセシビリティ検査も含みます。

すでに起動したローカルサーバーを使う場合は、任意の`PLAYWRIGHT_BASE_URL`を指定します。この場合Playwrightはサーバーを起動しません。

```bash
PLAYWRIGHT_BASE_URL=http://127.0.0.1:5173 pnpm test:e2e
```

Windows PowerShellの場合は環境変数の指定を`$env:PLAYWRIGHT_BASE_URL = "http://127.0.0.1:5173"`とし、同じシェルで`pnpm test:e2e`を実行します。既存サーバーの利用時も、ブラウザーと依存関係はテストを実行するOS側にインストールします。

失敗時は`playwright-report/`と`test-results/`に結果・スクリーンショット・トレースが残ります。`pnpm exec playwright show-report`でHTMLレポートを開けます。実施環境、結果、手動で残る確認は[品質レビュー記録](../docs/frontend-quality-review.md)を参照してください。自動検査の成功だけで、実機操作やスクリーンリーダーでの検証が済んだとは扱いません。

## 個別解析・共有・追跡の追加案（チーム未合意）

利用者が提案した「脆弱性情報版VirusTotal」の操作案です。チームで採用が決まった機能ではありません。フル版の `http://localhost:5173/#/analyze` で試せます。

| 操作 | モックで確認できること |
| --- | --- |
| CVE・GHSA・公開アドバイザリURLを入力 | 既存結果があれば再利用し、なければ処理待ち→情報収集→解析→結果の導線を表示。操作例は `CVE-2025-10000`。このIDの存在や内容は検証しない |
| 再解析 | 直前の結果を残して処理を開始し、完了後に更新履歴を追加する |
| 追跡期限 | 追跡7日・確認間隔1日という暫定値。期限切れ後の手動再解析では自動追跡を再開せず、別の追跡再開操作で7日間を設定する |
| 過去情報を含むリポジトリ検索 | 固定プロフィールの結果と過去情報2件を照合し、既存分析の再利用と新規解析の待ち時間を確認する |
| 新着レポートの反映 | 起動後30秒で固定記事 `demo-013` を1件だけ追加候補にする。利用者が反映するまで閲覧中の一覧を変えない |
| 記事の共有 | 対応ブラウザーではOSの共有機能、それ以外は記事URLのコピーを使用する |

解析操作の約6秒の待ち時間はブラウザー内の演出です。実際のクロール・LLM実行・サーバーの定期ジョブはありません。定期確認もこの画面を開いている間のローカル処理です。既存記事と過去記事の本文は固定データで、新しく入力したCVE等は処理演出が完了しても対象製品・バージョン・CVSSなどを「未確認／未評価」のままにします。

追加入力と解析履歴は同じタブのsessionStorageに保存します。保存した記事の入力情報はプロフィールにも保持するため、ログインと保存の再現で説明した方法で復元できます。

共有は記事URLの受け渡しです。画像・本文をアップロードする機能や、サーバー上にレポートを保存する機能はありません。`localhost`のURLは別端末から開けません。別のセッションにURLだけを渡しても、そのセッションに存在しない追加入力の記事は取得できません。外部共有を製品機能にするには、バックエンドでのレポート保存と公開・権限の設計が必要です。

URL入力の形式を検証しても、その情報源の存在・信頼性は保証できません。「過去情報を含む」は調査範囲の選択を示すもので、モックが過去の全脆弱性を取得・網羅する意味ではありません。新しいAPIを想定する際の論点は [連携メモ](../docs/frontend-integration.md#個別解析期限付き追跡の追加案チーム未合意) にまとめています。
