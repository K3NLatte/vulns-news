# フロントエンドのモック

脆弱性フィードの画面と操作を確認する、Vue＋TypeScriptのローカルモックです。バックエンドAPI、クローラー、LLMには接続していません。

記事、製品、脆弱性ID、スコア、悪用状況、分析結果はすべて架空のサンプルです。記事のCWEリンクは一般参考であり、その記事の根拠ではありません。

## 起動

Nixを導入済みのWSL Ubuntu-24.04を使います。PowerShellから開く場合は、次を実行します。

```powershell
wsl -d Ubuntu-24.04
```

リポジトリのルート（`flake.nix` があるフォルダー）に移動してから、WSLのターミナルで実行します。

```bash
nix develop path:.
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

ブラウザーで <http://localhost:5173> を開きます。ポートが使用中の場合は、ターミナルに表示されたURLを使ってください。開発サーバーは `Ctrl+C` で停止します。

`node_modules` の作成とコマンド実行はWSL／Nix内で行ってください。同じフォルダーに対してWindows側のpnpmを併用すると、実行ファイルやOS別の依存関係が混在します。

Windows側のエディターで保存した変更も検知するため、開発サーバーはポーリングでファイルを監視します。

現在は型検査ツールとの互換性のためTypeScript 5.9.3に固定しています。`pnpm install --frozen-lockfile` は、同梱のlockfileに従って依存関係をそろえます。

## 試せること

- 一般フィード：架空の記事12件を表示します。
- リポジトリ向け表示：公開GitHubリポジトリ形式のURLを入力すると、依存関係を想定した6件を表示します。どの有効なURLでも同じサンプルです。リポジトリの存在・公開状態・依存関係を調べる機能はありません。
- 検索、重要度の絞り込み、新着順／重要度順の並び替え、記事詳細の確認。
- 「表示状態を試す」から通常、読み込み中、0件、エラーへ切り替え。「通常」を選ぶと戻ります。

入力したリポジトリURLと検索内容を外部へ送信しません。参考リンクを明示的に開くと、その外部サイトへ移動します。入力や選択状態は画面内だけで保持し、再読み込みするとリセットされます。

## 開発時の確認

起動手順と同じWSL／Nix環境の `frontend/` で実行します。

```bash
pnpm typecheck
pnpm test
pnpm build
```

- `typecheck`：VueとTypeScriptの型を確認します。
- `test`：データ取得境界のURL検証、検索、並び替え、キャンセルなどを確認します。
- `build`：型検査後、配布用ファイルを `dist/` に生成します。デプロイは行いません。

画面の見切れ、キーボード操作、スマートフォン幅、各表示状態はブラウザーでも確認してください。

## データ取得の境界

画面の状態は `src/composables/useFeed.ts`、取得処理は `src/services/feed.ts`、画面用の型は `src/types/feed.ts`、サンプルデータは `src/mocks/feed.ts` に分けています。画面からサンプルデータを直接参照しない構成です。

Go側との接続で確認する事項と移行手順は、[フロントエンド連携メモ](../docs/frontend-integration.md)にまとめています。
